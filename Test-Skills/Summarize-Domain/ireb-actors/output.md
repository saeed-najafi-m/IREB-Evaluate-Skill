# Actors: GOV.UK Notify

No documents were provided, the GOV.UK Notify Data Processing and Financial Agreement (PDF) could not be read and is therefore not used, and most of the official web pages used do not state an edition or date.

| ID | Name | Goals | Tasks | Data flows | Sources |
|---|---|---|---|---|---|
| ACT 1 | Public sector organisation (service user organisation) | Send transactional emails, text messages (SMS) and letters to the people it serves without procuring its own messaging infrastructure, as the data controller (the party deciding how personal data is used) for the message data. | Accepts the terms of use and the data processing and financial agreement, confirms that Notify meets its own information, cyber security and data protection standards, and pays for text messages beyond the free allowance and for letters via a purchase order (PO). | **To system:** acceptance of the terms of use and of the organisation agreement<br>**To system:** confirmation of recipient consent and data accuracy<br>**From system:** notices of changes to the terms or delivery providers (30 days' email notice) | SRC 1, SRC 2, SRC 3, SRC 6 |
| ACT 2 | Service manager (team member with the "Manage settings, team and usage" permission, also the billing contact) | Keep the organisation's Notify service correctly set up, secure and within budget. | Configures email, text and letter settings, branding and the data retention period, adds and removes team members and assigns permissions, requests daily limit changes and the move from trial mode to live, and monitors usage and spend. | **To system:** service settings (sender details, branding, data retention period, daily limit requests)<br>**To system:** team member invitations, permissions and removals<br>**To system:** request to go live<br>**From system:** usage figures (messages sent, remaining free text messages, spend) | SRC 1, SRC 4, SRC 5, SRC 8 |
| ACT 3 | Template editor (team member with the "Add and edit templates" permission) | Provide clear, correct message content that meets the GOV.UK Service Manual writing standards. | Creates, edits and formats email, text message and letter templates, including placeholders for personalised content and letters uploaded as PDF. | **To system:** template content and formatting<br>**To system:** letter PDFs for upload<br>**From system:** template previews | SRC 1, SRC 4, SRC 9 |
| ACT 4 | Message sender (team member with the "Send messages" or "See dashboard" permission) | Get individual or bulk messages to the right recipients and know whether they arrived. | Sends messages from templates to one or many recipients through the web interface, chooses reply-to addresses and postage, and checks delivery status on the dashboard. | **To system:** recipient contact details (email address, mobile number, postal address) and personalisation data<br>**To system:** choice of reply-to email address and postage<br>**From system:** delivery status of each message (e.g. delivered, email address does not exist, technical failure) | SRC 4, SRC 5, SRC 9, SRC 10 |
| ACT 5 | Developer of the organisation's digital service (team member with the "Manage API integration" permission) | Let the organisation's own systems send messages automatically and react to delivery results. | Integrates with the Notify REST API (Application Programming Interface), manages and rotates API keys (test, team and guest list, live), and sets up callbacks (Notify's automatic calls to a URL of the organisation's system). | **From system:** API keys<br>**To system:** send requests (template ID, recipient, personalisation, reference, precompiled letter PDF)<br>**From system:** notification ID and message details in response<br>**To system:** callback URL and bearer token<br>**From system:** delivery receipts, received text messages and returned letter details via callbacks<br>**To system:** reports of compromised API keys | SRC 1, SRC 4, SRC 7 |
| ACT 6 | Message recipient (member of the public or other person contacted by a public sector organisation) | Receive timely, relevant information about a transaction or subscription from a public service. | Receives emails, text messages and letters, and can reply by text message where the service has set up receiving text messages. | **From system:** emails, text messages and letters<br>**To system:** text message replies | SRC 1, SRC 7, SRC 8, SRC 9 |
| ACT 7 | GOV.UK Notify team at the Government Digital Service (GDS) | Run a secure, reliable shared messaging platform for the public sector, acting as data processor for message data and controller for account data. | Operates and supports the platform, reviews go-live requests against the terms of use, handles security incident reports, publishes service status and performance data, and grants privileged production access only temporarily for specific change requests or support tickets. | **To system:** go-live decisions<br>**From system:** team member account data (name, email address, mobile number, IP address) for access checks and activity records<br>**To system:** service status and performance information | SRC 1, SRC 3, SRC 5, SRC 8 |
| ACT 8 | GDS Business Operations (finance function of the operator) | Recover the costs of text messages and letters from customer organisations. | Records purchase orders and finance contacts and issues quarterly invoices with each service's spend. | **From system:** spend per service for invoicing | SRC 6 |
| ACT 9 | Delivery providers (third-party suppliers for email, text messages and letters, and their sub-processors) | Deliver messages on behalf of Notify under a contract or memorandum of understanding with Notify's security requirements. | Accept messages from Notify, deliver, print and post them, and report the delivery outcome back. | **From system:** message content and recipient contact details<br>**To system:** delivery status information<br>**To system:** returned letter details | SRC 1, SRC 7, SRC 8, SRC 10 |
| ACT 10 | Law enforcement authorities | Obtain message data where legally required. | Request and receive access to data held by Notify where the law requires it. | **From system:** stored message and recipient data | SRC 8 |
