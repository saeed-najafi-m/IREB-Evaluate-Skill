# Glossary: GOV.UK Notify

No documents were provided, and the Data Processing and Financial Agreement (PDF) could not be read, so this glossary uses only GOV.UK Notify's web pages; the official REST API (Application Programming Interface) documentation serves as the primary source.

| ID | Term | Abbreviation | Definition | Note | Sources |
|---|---|---|---|---|---|
| GT 1 | API key | – | A credential that a service uses to send messages through the Notify API. There are three types: a *test* key returns realistic responses but delivers nothing and does not count against allowances; a *team and guest list* key sends real messages only to the team and the guest list while the service is in trial mode; a *live* key, available only after go-live, sends to anyone and counts against allowances. | The terms of use require keys to be encrypted at rest and in transit, not hard-coded, and rotated at least once a year, when someone with access leaves, or when a compromise is suspected. | SRC 1, SRC 9 |
| GT 2 | Callback | – | A POST request that Notify sends to a URL provided by the service, authenticated with a bearer token the service supplies. Callbacks report delivery receipts, received text messages and returned letters. If a callback fails, Notify retries it every 5 minutes, up to 5 times. | – | SRC 1 |
| GT 3 | Daily limit | – | The maximum number of messages a service may send per day. A live service may send 250,000 emails, 250,000 text messages (of which 100 international) and 20,000 letters per day. Limits reset at midnight UTC (Coordinated Universal Time). | In trial mode the API documentation gives 50 emails *or* text messages for team keys, while the trial mode guidance gives 50 emails *and* 50 text messages per day. The API documentation is preferred as the specification; the difference should be clarified. | SRC 1, SRC 6 |
| GT 4 | Data controller and data processor | – | The organisations that send notifications through Notify are the data controllers for the message data; GDS (Government Digital Service) acts as the data processor. For the login details of Notify users, GDS (part of the Department for Science, Innovation and Technology) is itself the controller. | The source assigns these roles but does not define the general legal terms; the legal definitions (UK data protection law) were not read. The processing relies on the lawful basis "public task". | SRC 8 |
| GT 5 | Free text message allowance | – | A yearly number of free text messages given to each eligible service, depending on the organisation type: 20,000 for central government departments and national organisations, 10,000 for local authorities and regional organisations, 5,000 for state-funded schools and other organisations, and none for GP surgeries. It renews on 1 April; unused messages expire on 31 March. After it is used up, each further message is charged. | Only one service of its kind per team or department qualifies, and test services do not. GP surgeries also cannot send text messages in trial mode. | SRC 3, SRC 7 |
| GT 6 | Go-live request | – | The request a service submits on the "Make your service live" page, after completing the listed tasks, to leave trial mode. Approval can take up to one working day because the Notify team checks that the service meets the terms of use. | – | SRC 6 |
| GT 7 | Guest list | – | Up to 5 additional email addresses or phone numbers, beyond the team, that a service may message with a team and guest list API key while it is in trial mode. | The trial mode guidance mentions only messaging yourself and your team members; the guest list is described only in the API documentation. | SRC 1, SRC 6 |
| GT 8 | Message status | – | The delivery state Notify shows for a message. For emails: *delivering* (passed to the provider, which may keep trying for up to 72 hours), *delivered* (the provider delivered it; Notify cannot tell whether it was opened or read), *email address does not exist*, *inbox not accepting messages right now* (e.g. full inbox or spam filter), and *technical failure* (a fault between Notify and the provider; the message must be sent again). | The API uses different status values: e.g. `sending` instead of "delivering", `permanent-failure` and `temporary-failure`; text messages also have `pending` and `sent` (international); letters have `accepted`, `received` and `cancelled`. The guidance pages for text message and letter statuses could not be retrieved. | SRC 5, SRC 1 |
| GT 9 | Personalisation | – | The values that fill the placeholder fields of a template, given as key–value pairs when a message is sent. In emails and letters, a list value is shown as bullet points; letters also require address lines. | – | SRC 1 |
| GT 10 | Postage class | – | The Royal Mail delivery option for a letter: *economy* (cheapest, 3 to 6 working days), *second class* (the default), *first class*, or *international*. Notify detects international addresses and applies international postage automatically. | Notify does not offer tracked delivery. Prices are stated per sheet, excluding VAT (value added tax), and may change. | SRC 4, SRC 1 |
| GT 11 | Precompiled letter | – | A letter that the service prepares itself as a PDF (Portable Document Format) file meeting Notify's letter specification, and sends to the API as a base64-encoded string, instead of using a Notify template. | Precompiled letters have extra statuses, such as `pending-virus-check`, `virus-scan-failed` and `validation-failed`. | SRC 1 |
| GT 12 | Rate limit | – | A rolling limit of 3,000 messages per 60 seconds for each API key type. Exceeding it returns the error 429 `RateLimitError`. | Distinct from the daily limit (GT 3). | SRC 1 |
| GT 13 | Reference | – | An identifier that the service creates for one message or a batch of messages. It must not contain personal information such as names or addresses. | – | SRC 1 |
| GT 14 | Reply-to email address | – | An email address that the service specifies to receive replies from recipients. At least one must be added before the service can go live. | In the API it is referred to as `email_reply_to_id`. | SRC 1 |
| GT 15 | Sheet | – | One piece of paper printed on both sides; the unit on which letter prices are based. A letter can have up to 5 sheets (10 pages). | The price includes paper, postage, double-sided colour printing and a C5 window envelope. | SRC 4 |
| GT 16 | Template | – | A saved email, text message or letter with placeholder fields, identified by an ID, name, type and version, with a subject and body. The API uses the latest version unless a specific version is requested. | A text message template may count as several messages for billing: up to 160 standard characters is one message, and fewer characters per message apply for non-standard characters (e.g. Welsh). | SRC 1, SRC 2 |
| GT 17 | Text message sender ID | – | A unique identifier of the sender of a text message, set in the service's settings. It is optional if the service has only one sender or wants to use the default. | In the API it is referred to as `sms_sender_id`. | SRC 1 |
| GT 18 | Trial mode | – | The state in which every new service starts. The service can only message its own users, team members (and, with a team and guest list key, the guest list), has a low daily limit, and cannot send letters, although letter templates can be created and letters uploaded. The restrictions are lifted after a successful go-live request. | See GT 3 and GT 7 for differences between the sources. | SRC 6, SRC 1 |
