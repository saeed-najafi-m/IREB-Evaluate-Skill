# System Context: GOV.UK Notify

No organisational documents were provided, the official sources do not name GOV.UK Notify's suppliers (sub-processors), and the GOV.UK Notify data processing and financial agreement (non-Crown version 6) could not be read as text, so it is not used.

GOV.UK Notify is the UK Government Digital Service (GDS) platform that public-sector teams use to send emails, text messages (SMS, Short Message Service) and letters. The sending organisation is the data controller and GDS is the data processor [SRC 4].

## System boundary issues

- **Amazon Web Services (AWS) hosting platform** - Notify runs on AWS in the UK and Ireland. It is the infrastructure underneath Notify, not a communication partner, and is normally treated as inside the boundary or as a platform dependency [SRC 5].
- **Two-factor sign-in (text message code or email link)** - Notify sends its own sign-in codes and links, probably through the same email and text message providers (ES 4, ES 5). It must be decided whether user authentication is part of the system or a separate component [SRC 5].
- **Mobile network operators and recipients' mail servers** - They receive messages through the providers (ES 4, ES 5), and text messages are also processed in the country of the recipient's phone. Decide whether to show them as indirect neighbours or leave them out [SRC 3, SRC 5].
- **One-click unsubscribe URL** - The sending organisation supplies the URL, and recipients' email clients call it on the organisation's own system, not on Notify. The unsubscribe handling may lie outside the boundary [SRC 1].
- **Sending organisation's back-office system and callback endpoint (ES 1, ES 2)** - These may be one system or several. They are shown separately because the callback channel is configured on its own [SRC 1].
- **Supplier assurance and billing** - GDS assesses suppliers and has a data processing and financial agreement with customers. Any billing or usage-reporting system was not found in the sources read [SRC 5].
