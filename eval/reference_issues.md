## Issues found in the reference

These observations concern `Inputs/expected-requirement.json`, not the runs. They are reported for review by the reference owner. All quotes are verbatim from the interview.

1. **Similar wording is treated differently.**
   - Included as a requirement: REQ 4, "Then I would also like to be able to edit the data in Excel".
   - Excluded as preferences: bulk selection and deletion, "What I would like is to be able to select a large number of entries", and saving filters, "I'd really like to have that too".
2. **Some exclusions cite weaker wording than the interview contains for the same topic.**
   - Sorting is excluded based on "that's something I could use". The same passage says "I really miss the sorting functions".
   - Keyboard-based operations are excluded based on "That would be great". The interview also says "it would also be important that I can do it quickly".
   - Bulk selection and deletion is excluded as a preference, but the statement continues "but that's not possible at the moment".
3. **One topic is neither included nor excluded:** selecting several entries for form letters ("that doesn't work either, I can only ever select one entry").
4. **The level of detail differs between requirements.** REQ 2 combines identical behaviour with table-specific single or multiple selection, although the two can be tested independently. The patient search is split into two requirements (REQ 8 and REQ 9).
5. **The excluded topics quote only short fragments** ("That would be great."), so they cannot be traced to a single place in the interview.
